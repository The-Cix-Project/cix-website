Cix OS · Open source

A Linux OS for
container hosts.

Install Cix on a dedicated machine or VM. Run your applications in containers. Use the web dashboard, CLI or REST API to manage their networks, storage and hardware.

Workloads

Give each service what it needs.

A deployment describes the image to run, the processes to start and the resources the container can use. Manage deployments →

Run an application

Declare its services and check their readiness. Read logs or open a configured container console from the dashboard.

Connect it to your network

Attach a container to a bridge or give it a physical interface. Configure addresses, routes and VLANs through the host API.

Keep data across updates

Mount a persistent volume for application data. When an update replaces the container root, the data stays on the volume.

Assign a physical device

Grant a workload access to a supported device, such as a USB radio. Use a named mapping when the deployment needs to refer to the same hardware again.

Network services

Keep your DNS records when you replace a server.

Manage DNS records in Cix. The host supplies them to registered dnsmasq containers, which answer queries on your network. Replacing a provider leaves the records on the host.

Host updates

Update the OS while your containers run.

Cix stages an updated system image in the inactive boot slot. When the kernel stays the same, the new control plane can take over running containers. Reconnect management clients after the switch. A kernel change requires a reboot.
