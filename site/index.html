Open-source Linux for container hosts

One host API.
A role for each agent.

Cix is a Linux operating system for container workloads. Its control plane serves the CLI, web dashboard and Model Context Protocol (MCP). Give each agent its own LDAP identity. The same role-based permissions govern its tools and the underlying API calls.

Host updates

Replace the control plane while containers run.

On 16 November, a Cix host switched to release 0.2.57-690 on slot A. All 14 containers kept their process IDs. The management API was away for 20 seconds while the new daemon took over.

Cix can make this handover when the kernel stays the same. A kernel change takes effect on reboot.

Control the real machine

Assign hardware to a workload.

Cix makes host mechanisms visible as policy-driven API resources—from the identity a container runs under to the physical port a device occupies and the disk where state lives.

01 / Isolation

Namespace containers by default.

Workloads use Linux namespaces, cgroup v2 controls, and user namespaces by default. Their image-derived roots are presented through id-mapped mounts; trusted internal build containers may opt out where required. Capability bounding-set trimming still applies, and this remains a container boundary rather than a virtual machine.

  • Linux namespaces, user namespaces, and cgroup v2
  • Id-mapped image-derived roots
  • Explicit boundary: not a virtual machine
ContainerCreateRequest.userns
02 / Hardware

Name hardware once. Resolve it live.

Grant PCI, USB, GPU, raw disk, or physical network hardware by discovered ID or an operator-named device map. Exact mappings pin a bus/port location; vendor-model mappings follow matching hardware when it moves.

  • BPF cgroup device enforcement
  • Optional devices + USB hotplug reaction
  • Atomic live attach and revoke
/v1/devicemaps
03 / Storage

Place storage by intent.

Discover real disks and partitions, assign closed operational roles, format ext4 or btrfs, and migrate storage without inventing a parallel storage registry. The OS disk is protected from role assignment and formatting.

  • State, logs, builds, backups, swap
  • Snapshot-backed roots and kernel quotas
  • Persistent volumes with enforced size limits, live usage, snapshots, and restore
/v1/storage-roles

Boundary: Cix containers use namespaces, not a hypervisor. Device grants are direct container access—not a VFIO/IOMMU virtual-machine isolation boundary. The installer also supports a Secure Boot-capable installed boot chain.
