Recipes

Start with a versioned input.

A package recipe records its source, checksum, version, dependencies, and build environment. New package builds use CPDL in build.cbs, executed by CBS; image recipes are JSON. Sibling packages and outputs converge together when a recipe changes, preventing mixed-version path ownership. Older published shell recipes are historical; Cix no longer builds them.

build.cbsCPDL 1.0CBSJSON imagescix-recipes
02

Artefacts

Use a cache hit or build from source.

Cix Cache may provide a prebuilt package whose identity and SHA-256 match the recipe. For a current CPDL/CBS recipe, a cache miss can trigger a source build. Package outputs are first-class artefacts, and an assembly refuses a missing output rather than falling back to an ambiguous build directory. Installer releases are signed and verified before publication.

recipeoutputsSHA-256minisignrelease gate
03

Self-hosting

Build the platform from a Cix host.

A running Cix host can build cixd, cixctl, the dashboard, the kernel, and a fresh installer ISO. The root and installer take the control-plane files from declared outputs, and cix-root keeps the assembled root aligned with those package boundaries. A hostbuild can report its build identity so an operator can confirm what actually booted.

hostbuildkernel-modulescix-rootrootfsISO assemblybuild identity

Build feedback

Follow the work while it runs.

The dashboard opens one floating log view for a running build. It follows the selected job, identifies which build produced the output, shows the current stage and elapsed time, and keeps the live log available while you inspect the rest of the host. Health also reports build identity, build time, and boot slot so a deployment can be confirmed after reboot.
