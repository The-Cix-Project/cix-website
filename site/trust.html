01 / Release integrity

Trust the signed file.

The Download page publishes the ISO, detached minisign signature, release key, key identifier, and SHA-256 values from one release manifest. Verify the signature on a machine you already trust before writing the image.

Open verification steps Review release keys

02 / What verification means

Useful proof, not a magic stamp.

A valid signature tells you that the downloaded bytes verify against the published Cix release key. It does not certify every machine, workload, configuration, or security property of the running system.

  • It provesThe ISO and detached signature match the release identity published by Cix and the signature verifies against the selected public key.
  • It does not proveThat your hardware is supported, that a workload is secure, or that an alpha release meets your production requirements.
  • It is reproducible to inspectThe manifest, source mirror, guides, API contract, and test evidence are public. A public source/build record is not the same as a formal reproducible-build guarantee.
  • It is independently checkableThe verification command uses minisign on a machine you already trust; it does not require trusting the website’s JavaScript.
03

Security boundary

Containers are not virtual machines.

Cix workloads use Linux namespaces and cgroups. User namespaces are not enabled by default, container processes currently run with real host UID 0, and direct device grants provide access to hardware rather than a hypervisor isolation boundary. Evaluate the boundary against the workload you intend to run.

04

Update safety

Write, verify, then cut over.

Host updates target the inactive A/B slot. Cix verifies the staged host before booting it and its EFI boot manager provides counted rollback. Read the update and recovery guides before relying on the mechanism for a machine that matters.

05

Compatibility

Supported paths are narrower than Linux.

The current installer targets UEFI x86-64 and documents specific storage, network, console, and hypervisor paths. Real GPU, physical-NIC, and wireless scenarios have narrower verification than software-only or emulated paths. Check the installation guide before choosing hardware.

06 / Project posture

Alpha means a real boundary.

Cix is available for evaluation and community use, but it does not yet publish formal support tiers, certifications, or a complete lifecycle commitment. For now, report suspected security vulnerabilities privately to osakka@gmail.com with the subject “Cix security report”; do not put sensitive details in a public issue. This is a maintainer contact, not a bug bounty or guaranteed response SLA.
