Trust and limits

Who can change your host?

An installer signature identifies the bytes you boot. Once Cix is running, directory groups govern access to the API, app passwords identify automation, and Linux namespaces constrain container processes.

Directory access

An agent cannot grant itself a larger role through the identity API.

Enable MCP explicitly and give each agent an LDAP user and a revocable app password. Its groups decide which tools it sees and each call is checked again. The standard agent group grants reads and gateway access.

The credential itself cannot authorise identity writes, even when its user belongs to an admin group. Audit entries name the identity and the app password used. A grant such as services:write covers the service area, including both DNS records and servers.

Security boundary

Workloads share the host kernel.

Cix workloads use Linux namespaces, cgroups, and user namespaces by default. Their image-derived roots are presented through id-mapped mounts; trusted internal build containers may opt out where required. Direct device grants provide access to hardware rather than a hypervisor isolation boundary, so evaluate the boundary against the workload you intend to run.

02

Update safety

Write, verify, then hand over.

Host updates target the inactive A/B slot. When the kernel is unchanged, Cix can hand the running control plane to the staged root in place: the successor validates the handover, running containers remain running, and the slot is confirmed only once the new daemon serves. Kernel changes reboot. A refused in-place switch uses the staged slot’s normal boot path. A startup failure after the root switch reboots into the held previous slot. See the handover and recovery sequence.

Compatibility

Supported paths are narrower than Linux.

The current installer targets UEFI x86-64 and documents specific storage, network, console, and hypervisor paths. Real GPU, physical-NIC, and wireless scenarios have narrower verification than software-only or emulated paths. Check the installation guide before choosing hardware.

Installer integrity

Verify the installer offline.

The Download page publishes the ISO, detached minisign signature, release key, key identifier, and SHA-256 values from one release manifest. Verify the signature on a machine you already trust before writing the image.

Project posture

Security reports and alpha support.

Cix is available for evaluation and community use, but it does not yet publish formal support tiers, certifications, or a complete lifecycle commitment. For now, report suspected security vulnerabilities privately to osakka@gmail.com with the subject “Cix security report”; do not put sensitive details in a public issue. This is a maintainer contact, not a bug bounty or guaranteed response SLA.
